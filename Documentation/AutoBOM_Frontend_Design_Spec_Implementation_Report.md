# AutoBOM Frontend Design Spec Implementation Report

Reimplements `app.py`'s UI to match `frontend/*.dc.html` (a design-tool
prototype package) and `Claude_Code_Frontend_Integration_Handoff.md`,
reusing the existing backend (`src/pagination.py`,
`src/partsbox_inventory.py`, `src/record_filter.py`,
`src/search_events.py`, `src/inventory_location_recommender.py`,
`src/review_actions.py`, `src/customer_reference*.py`,
`src/workflow_runner.py`, `ActiveBomState`) exactly as the handoff's
component→backend mapping table specified. No `src/` files changed in
this pass -- see "Deferred, by explicit decision" below.

## Why the `.dc.html` files were not embedded directly

`frontend/` is generated by a separate design-tool ("dc-runtime", a
bespoke React-based prototyping renderer loaded via `frontend/support.js`)
-- confirmed via that file's own header comment
(`// GENERATED from dc-runtime/src/*.ts`) and its `<x-dc>`/`sc-if`/
`sc-for`/`dc-import`/`DCLogic` mechanics, none of which are Streamlit
APIs. This is not something `st.components.v2` can mount (that path
requires Streamlit's own packaged-component pipeline -- cookiecutter
template, npm build, `asset_dir` with globbed js/css -- not an ad hoc
multi-file tree with `<dc-import>` cross-references). The handoff
document itself confirms this reading ("Reimplement the *root's* state/
effects in Streamlit... there is no `st.session_state`... in a DC"), so
the `.dc.html` files were used as a precise, executable **behavior/
layout spec** -- read in full, not run -- the same role the earlier PNG
mockup played in the prior pass, just far more exact (every prop/event
contract, every conditional-visibility rule, every pagination/height
constant, and a complete reference implementation of the state-
management logic in the root file's `renderVals()`).

## Deferred, by explicit decision (asked the user; confirmed: defer both)

Two things the spec wants would have required real `src/` changes, not
reshapes -- confirmed by reading the actual code before assuming either
way:

1. **Facet value counts** (e.g. "Yageo (42)"). `record_filter.generate_facets()`
   returns `{field: sorted distinct values}` with no counts. Every
   Basic Filter and Component Characteristic value in this pass renders
   as a plain value, not `"value (count)"`.
2. **A real "DNP" (Do Not Populate) terminal status**, the spec's 4th
   Needs Review action. Checked `active_bom_state.py` directly:
   `result_status` is fully derived every read
   (`_derive_result_status()`/`_needs_review()`) from raw
   `status`/`supplier_match_status`/`sourcing_status`/
   `partsbox_match_status` columns -- there is no existing DNP concept
   anywhere in `src/` (confirmed via grep), and writing
   `update_row(row_id, {"result_status": "DNP"})` would silently do
   nothing, since the next read recomputes it fresh from those columns.
   Needs Review keeps its current 3 actions (Retry Exact / Find
   Replacement / Check PartsBox); `NeedsReview.dc.html`'s
   `onMarkDnp`/`selectedItemId` props are simply not wired to anything.

Everything else in the mapping table checked out exactly as claimed,
confirmed by reading the actual current signatures of every function
named (not assuming the handoff's recollection was accurate):
`pagination.paginate/clamp_page/total_pages_for/result_signature`,
`record_filter.generate_facets/apply_filters/search_and_filter`,
`partsbox_inventory.get_snapshot/InventoryPart.to_dict()`,
`customer_reference.*`/`customer_reference_registry.*`,
`inventory_location_recommender.recommend_location()`,
`active_bom_state.py`'s row/summary/review methods,
`workflow_runner.build_purchasing_summary()`/`derive_purchasing_status()`
(real, exactly named -- the handoff was right, contrary to my own
suspicion going in), `review_actions.retry_exact_sourcing/apply_replacement`,
`component_lookup.build_query_from_bom_row/search_components`.

## What changed in `app.py`

- **No sidebar navigation.** The separate "PartsBox Inventory" page and
  its Storage Locations sub-section (`render_partsbox_inventory_page()`,
  `render_inventory_selected_part_details()`,
  `render_partsbox_storage_locations()`) are deleted entirely -- a
  single continuous page now. Browsing the full PartsBox catalog is a
  new **"Browse Inventory"** button inline in Main Search's PartsBox
  panel (a new `pbState`-equivalent gate alongside typing), not a
  separate destination.
- **Manufacturer is now a membership facet** (checkbox-style
  `st.multiselect`), not a free-text exact-match input, applied across
  whichever records currently exist (PartsBox and/or supplier);
  Storage Space/Location/Project stay PartsBox-only.
- **Component Characteristics**: a new collapsible filter surface
  (`render_component_characteristics()`) over parametric fields
  (package/voltage/tolerance/dielectric/mounting) -- reuses
  `generate_facets()`/`apply_filters()`, the same engine Basic Filters
  uses, as a second UI entry point, not a second engine. Entirely
  hidden when the current PartsBox result set has no such fields.
- **Fixed-height, fixed-page-size Discovery Results.**
  `_render_paginated_table()`/`_pagination_controls()` were generalized
  to take a `page_size`/`height` per call (previously hardcoded to
  `pagination.DEFAULT_PAGE_SIZE=20`). Main Search's PartsBox/Supplier
  tables now use `DISCOVERY_PAGE_SIZE=14` (the spec's own demonstrated
  constant -- its prose elsewhere says 20, contradicting both that
  constant and its own "target 12-15" instruction, so 14 was the
  correct read) and a fixed `st.dataframe(height=...)` regardless of
  result count.
- **Working Parts List** (`render_working_parts_list()`) replaces the
  old "All Results" tab: its own presentation-only pagination
  (`WORKING_LIST_PAGE_SIZE=10`, independent of the canonical BOM's
  actual size), and an **inline-editable Customer Reference cell**
  directly in the grid via `st.data_editor(disabled=[every other
  column])` -- Streamlit's real native equivalent of the spec's
  editable grid cell (discovered mid-implementation; a much better fit
  than the manual per-row text-input approach originally sketched in
  the plan). Streamlit has no commit-on-blur; an edit commits on the
  next rerun instead (a disclosed simplification).
- **Needs Review becomes a master-detail layout**
  (`render_needs_review_section()`): a narrow list column
  (`st.radio`, keyed `selected_review_row_id`) plus a wide detail pane
  with the 3 actions and the replacement-search sub-panel, replacing
  the old per-row `st.expander` list. Selecting a different row clears
  any open replacement panel (tracked via a `_needs_review_shown_row_id`
  shadow key, since `st.radio`'s own value doesn't expose "did this
  change this render").
- **Configuration's Customer Reference control** is now a compact
  summary line + an **"Edit Customer Reference" `st.popover()`**
  (`render_customer_reference_summary()`), not an always-expanded
  inline section -- the popover body is the same
  `render_customer_reference_section()` as before (radio + Project/PCB/
  R&D/Inventory generators + per-line overrides + add-code disclosure),
  unchanged internally. The PartsBox-write toggle gained two-tone
  microcopy (distinct explanatory caption for on vs. off, not a static
  tooltip).
- **`st.toast()`** replaces `st.success()` for the Add-to-BOM
  confirmation (the spec's transient `addedConfirmation` message) --
  Streamlit's native equivalent, no custom timeout logic needed.
- **Selected Part Details** now branches by kind: PartsBox rows show
  locations grouped by storage space (Development/Project/Mechanical/
  Other), one table per group; supplier rows show a 3-tile Stock/Unit
  Price/Supplier P/N row via `st.metric`.
- **Purchasing Handoff's "Outputs" section renamed "Other Outputs"**
  and now excludes `mouser_export_csv` (shown inline in the Mouser
  panel with its own bespoke button, per the spec -- not duplicated);
  `digikey_list_csv` stays reachable there even though DigiKey's own
  panel has no download button (matches the spec's asymmetry: DigiKey's
  MyList is opened externally, only its List ID/Share ID are shown
  inline) -- kept rather than made unreachable, since the spec's
  `otherOutputs` example list is illustrative, not exhaustive, and
  removing existing capability wasn't asked for.

## Native-Streamlit equivalents (not literal ports)

Streamlit has no local-only/no-rerun widget state, so several spec
behaviors were mapped to their closest native primitive rather than
reproduced pixel-for-pixel:

- Long facet/membership lists → `st.multiselect`'s own built-in
  type-to-filter dropdown (bounds the rail's rendered height regardless
  of option count) instead of the spec's bespoke "top 8 + Show more"
  truncation.
- Component Characteristics' add/remove chip picker → one
  `st.multiselect` choosing active fields (native per-chip "×" removal
  already matches) + one `st.selectbox` per active field.
- The spec's viewport-switcher/scale-to-fit preview harness (a
  design-tool-only affordance for previewing 1920/1440/1366 side by
  side) is not reproduced; Streamlit's own responsive `st.columns`
  behavior is what ships, same as the prior pass.
- Filters render inline (an `st.expander("Basic Filters")`), not as a
  literal persistent left-hand rail with a separate "Filters (N)"
  popover button at narrow viewports -- the compact/1366-breakpoint
  popover mode was not implemented (no JS-driven viewport-width
  detection available natively).

## Additional refinements from a second reference-document pass

Partway through, two more pre-existing repo documents surfaced --
`Documentation/AutoBOM_Interaction_Specification.md` and
`Documentation/Claude_Code_UI_Implementation_Handoff.md` -- an earlier
design-phase handoff pair, explicitly superseded by the one this pass
was built against ("this table specializes down to the actual component
boundaries now that they exist as real files"). Read in full and
cross-checked against the actual `.dc.html` files rather than assumed
stale outright: **one real contradiction** (the older spec says Working
Parts List should scroll internally rather than paginate; the actual
`WorkingPartsList.dc.html` code hard-codes `PAGE_SIZE=10` pagination) --
resolved in favor of the executable DC code, which is what this pass
already matched. Flagged this to the user along with **three real,
non-contradicting refinements** the newer handoff hadn't spelled out;
confirmed to add all three:

1. **Selected-row lifecycle.** A selection now clears when: a new Enter
   query commits (both result sets it could reference are about to
   change), the source that produced it gets unchecked, or the search
   draft transitions from non-blank to blank. It does **not** clear
   from an unrelated filter/page/quantity change or a PartsBox snapshot
   refresh. Implemented as explicit checks in
   `render_component_search_intake()` rather than folded into the
   existing pagination-reset signature, since this is a different rule
   (selection-clearing, not page-resetting) with different triggers.
2. **Stale supplier-results caption.** If the draft diverges from the
   last committed Enter query, the Supplier Results heading gains
   "Results are for '\<old query\>' -- press Enter to update." The
   results themselves are never cleared or greyed out while stale --
   only marked.
3. **Search box Clear ("✕") button.** Resets the draft to empty,
   clears supplier results and the last-submitted marker entirely (a
   blank query has no supplier meaning), and clears any current
   selection. Implemented via **widget-key rotation**
   (`component_search_event_generation`, incremented on each clear) --
   `search_event_input()`'s own remembered CCv2 state for a key always
   wins over a plain `value=` override once any real typing has
   happened, so the only reliable reset is mounting a fresh widget
   instance under a new key, not fighting the existing one's internal
   state.

Covered by a new `tests/test_app_navigation.py` class,
`SearchSelectionAndStaleResultsLifecycleTests` (4 tests): the Clear
button's full reset, source-uncheck clearing a matching selection, an
unrelated rerun *not* clearing a still-valid selection (the contrast
case), and the stale caption appearing/disappearing correctly as the
(simulated) draft diverges from and rejoins the last committed query.

## A real bug found and fixed mid-implementation

`_render_paginated_table()`'s new `height=None` default (for call sites
that don't fix a height, e.g. Needs Review's replacement-candidate
table) crashed every single such render with
`StreamlitInvalidHeightError: Invalid height value: None` --
`st.dataframe(height=...)` does not accept `None` as "auto" the way
some other elements do. Fixed by passing `height or "content"`. Found
via a manual reproduction script after several AppTest failures traced
back to the exact same stack frame; every affected test
(`test_selecting_a_replacement_updates_canonical_state_via_ui`,
`test_check_partsbox_search_uses_the_shared_snapshot_not_a_live_search`,
`test_uploading_while_a_working_bom_exists_merges_instead_of_replacing`,
all of `test_customer_reference_ui.py`'s purchasing-adjacent tests) was
re-verified green after the fix.

A second real bug, same investigation: `render_replacement_lookup()`'s
"Use Selected Replacement" handler wrote
`st.session_state.selected_review_row_id = None` -- legal before this
pass (a plain variable), illegal now that `selected_review_row_id` is a
real `st.radio` widget key already instantiated earlier in the same
script pass (`StreamlitWidgetAlreadyInstantiatedError`). Removed that
write; the row naturally drops out of `review_items()` once no longer
Needs Review, and `render_needs_review_section()`'s own pre-clamp logic
picks a fresh valid selection before the radio re-instantiates on the
subsequent rerun.

  detail selection.
